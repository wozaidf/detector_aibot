# L1 → L2 数据流与可视化看板

本项目用 Docker Compose 启动 Kafka、独立 L1 回放控制服务、Flink L2 和实时看板。首次启动需要先打开 Docker Desktop，然后在 PowerShell 执行：

```powershell
docker compose up -d --build
```

确认容器状态：

```powershell
docker compose ps
```

打开以下页面：

- L2 实时看板（数据流、规则命中、异常结果）：<http://localhost:8090>
- Flink 自带 Dashboard（作业和算子状态）：<http://localhost:8081>

确认 Flink 作业为 `RUNNING` 后，点击页面“500 条样本回放”区域的“回放 500 条样本”按钮。页面按 600× 速度读取 `L1生成结果/l1_windows.jsonl` 并发送到 Kafka 输入 Topic，同时显示进度。重放相同样本时，L2 的去重逻辑可能抑制重复异常。

也可以继续在 PowerShell 手工回放 500 条 L1 样本：

```powershell
Set-Location .\L2-stream
python -m l1_stream_simulator.replay L1生成结果/l1_windows.jsonl --speed 60 --kafka-bootstrap localhost:9092 --topic l1-aligned-windows
```

该命令由 L1 模拟器直接发送 Kafka。Dashboard 的回放按钮则通过 HTTP 调用 Compose 中的 `l1-replay` 控制服务；Dashboard 本身不读取样本文件，也不创建 Producer。容器内 L1 服务使用 `kafka:29092` 连接 Kafka。

`--speed 60` 表示按 60 倍模拟时间回放；测试时可改成 `600` 加快速度。数据发送后，看板会自动刷新 Kafka 输入计数、L2 输出、Drools/CEP 命中事件、规则命中统计和异常结果。结果可以按来源、严重等级、决策筛选，点击“详情”查看证据。

## 调整规则阈值

在看板右侧“规则参数”修改并保存，配置写入 `L2-stream/config/l2/rules.env`。当前 Flink 作业不会在运行中热加载规则；保存后，在工作区根目录执行下面命令重启 L2 作业以应用新阈值：

```powershell
docker compose up -d --force-recreate jobmanager taskmanager
```

重新评估同一批 500 条数据时，先确认 Flink 作业为 `RUNNING`，再重新发送样本。可在结果区对比每种规则命中数和输出事件。

## 查看原始异常 JSON

```powershell
docker compose exec kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server kafka:29092 --topic l2-anomaly-events --from-beginning
```

按 `Ctrl+C` 停止查看。

## 停止服务

```powershell
docker compose down
```

再次使用时运行 `docker compose up -d`；代码或 Dockerfile 有修改时运行 `docker compose up -d --build`。
